# 工具链与依赖

`[toolchain]` 声明工具链包，`[dependencies]` 声明库。两者都由 `heddle tool install` 安装。

## 清单

```toml
[toolchain]
cross-gcc = "arm-none-eabi@12.2.0"
nasm      = "2.16.01"
qemu      = "8.0.0"

[dependencies]
freertos = "10.5.1"
lwip     = "2.1.3"

[target]
arch  = "armv7em"
abi   = "eabihf"
float = "hard"
```

| 段 | 内容 |
| --- | --- |
| `[toolchain]` | 键是别名，值是 `名字@版本` |
| `[dependencies]` | 键是库名，值是 `版本` 或 `名字@版本` |
| `[target]` | 交叉目标，推出前缀、sysroot 和编译参数 |

`[toolchain]`（无点）是包列表；`[toolchain.host]`、`[toolchain.debug]` 仍然是编译器预设，两者不冲突。

store 位置可选：

```toml
[build]
store = ".heddle/store"   # 默认
```

## tool install

```sh
heddle tool install
```

1. 读 `[toolchain]` 和 `[dependencies]`；
2. 从 registry 取包到 `<store>/<kind>/<名字>/<版本>/`；
3. 对落盘内容做递归哈希；
4. 写 `heddle.lock`。

registry 取 `HEDDLE_REGISTRY` 或 `--registry`，可以是本地目录或 `http(s)://`：

```sh
heddle tool install --registry /srv/pkgs
heddle tool install --registry https://pkgs.example.com
```

`heddle tool plan`（别名 `list`）只打印解析结果：

```
$ heddle tool plan
heddle: plan
  architecture: armv7em abi=eabihf float=hard
  prefix:       arm-none-eabi-
  cflags:      -mthumb -mcpu=cortex-m4 -mfpu=fpv4-sp-d16 -mfloat-abi=hard
  toolchain  arm-none-eabi    12.2.0     auto
  library    freertos         10.5.1     auto
```

### registry 布局

```
<registry>/
  toolchain/<名字>/<版本>/          # 目录，含 bin/
  library/<名字>/<版本>/            # 目录，含 include/、lib/，或 package.toml
  <kind>/<名字>/<版本>.tar.gz       # 或打包形式
```

目录形式直接拷贝。tar.gz 解包后，如果顶层只有一个包裹目录（如 `10.5.1/`）会自动展开；
`bin/`、`include/`、`lib/`、`src/` 这类结构目录不会被展开。

工具链的 `bin/` 在构建时前置到 `PATH`。二进制库的 `include/`、`lib/` 拼成 `-I`、`-L`、`-l`。

## 源码包

库目录里放 `package.toml` 就是源码包。`tool install` 把源码取进 store，编译在构建时进行。

```toml
[package]
name = "freertos"
version = "10.5.1"

[source]
url = "https://github.com/FreeRTOS/FreeRTOS-Kernel.git"
tag = "V10.5.1"

[build]
sources = ["src/*.c", "port/*.asm"]
include_dirs = ["include"]
defines = ["configUSE_PREEMPTION=1"]
cflags = ["-Os"]
```

| 键 | 含义 |
| --- | --- |
| `sources` | 源文件，支持 `*` `**` `?` 通配，按后缀选编译器 |
| `include_dirs` | 头文件目录，相对包根 |
| `defines` | 追加 `-D<名字>` |
| `cflags` | 追加到编译命令 |

源码包不含 `include/`、`lib/`，产物由构建生成。

### 多语言

`sources` 里可以同时有 C 和汇编，按后缀分派：

```
0: gcc  -c ... -o out/greet_greet.o .heddle/store/library/greet/1.0/src/greet.c
1: nasm -f elf64 ... -o out/greet_level.o .heddle/store/library/greet/1.0/src/level.asm
2: ar rcs -o out/libgreet.a out/greet_greet.o out/greet_level.o
3: gcc -o out/app out/app_main.o out/libgreet.a
```

需要新语言就在 `heddle.toml` 里声明 `[lang.xxx]`，见 [语言插件](language-plugins.md)。

### 依赖进构建图

`[dependencies]` 里的源码包会变成构建图里的一个 `staticlib` 目标，和手写的
`[target.*]` 没有区别：进同一条 DAG，按内容哈希决定是否重编。

`type = "exe"` 和 `type = "sharedlib"` 的目标自动依赖这些包，不用写 `deps`。
其他类型的目标要用就得自己写。

## 变体

`[target]` 和工具链一起算出一个变体 key，格式是 `arch-工具链-十六进制`：

```
heddle: toolchain=arm-none-eabi platform=cross-arm-none-eabi variant=armv7em-arm-none-eabi-3f2a1c9d0e4b7a86
```

## 锁文件

`heddle.lock` 记录每个包的目录树哈希：

```
# generated by heddle; do not edit
toolchain arm-none-eabi 12.2.0 sha256:0f4802ee12ec1fb8
library freertos 10.5.1 sha256:f75a674924c70996
```

哈希按路径排序后递归计算，文件增删或内容变化都会改变。

`tool install` 会检查 store 内容：与锁不符时清掉重取。`--offline` 下不重取，直接报错。

## 离线

store 装好之后，不连 registry 也能构建：

```sh
heddle tool install        # 联网时一次
# 断网
heddle app
```

`heddle --offline tool install` 禁止访问 registry。

## env verify

```sh
heddle env verify
```

对比 store 实际哈希和 `heddle.lock`：

```
heddle: library freertos@10.5.1: drift (lock sha256:f75a..., store sha256:ac3c...)
heddle: environment does not match heddle.lock
```

一致时输出：

```
heddle: environment matches heddle.lock (1 toolchain, 1 dependency)
```

## [target]

```toml
[target]
arch  = "armv7em"
abi   = "eabihf"
float = "hard"
```

内置模板推出前缀和编译参数：

| arch | 前缀 | 编译参数 |
| --- | --- | --- |
| `armv6m` | `arm-none-eabi-` | `-mthumb -mcpu=cortex-m0` |
| `armv7m` | `arm-none-eabi-` | `-mthumb -mcpu=cortex-m3` |
| `armv7em` | `arm-none-eabi-` | `-mthumb -mcpu=cortex-m4 -mfpu=fpv4-sp-d16 -mfloat-abi=hard` |
| `armv8m` | `arm-none-eabi-` | `-mthumb -mcpu=cortex-m33` |
| `cortex-m7` | `arm-none-eabi-` | `-mthumb -mcpu=cortex-m7` |
| `aarch64` | `aarch64-none-elf-` | `-march=armv8-a` |
| `riscv32imac` | `riscv64-unknown-elf-` | `-march=rv32imac -mabi=ilp32` |
| `riscv64` | `riscv64-unknown-elf-` | `-march=rv64imac -mabi=lp64` |
| `xtensa` | `xtensa-esp32-elf-` | `-mlongcalls` |
| `avr` | `avr-` | `-mmcu=atmega328p` |
| `msp430` | `msp430-elf-` | `-mmcu=msp430f5529` |
| `x86_64` / `i686` | 空 | `-m64` / `-m32` |

`float` 取 `soft`、`softfp`、`hard`。不写 `[target]` 就是本机构建。

sysroot 可以显式写：

```toml
[target]
arch    = "armv7em"
sysroot = "/opt/arm/sysroot"
```

变成 `--sysroot` 和路径两个参数。arch 不认识时报错。

## 构建时

`heddle <target>` 加载工程时：

1. 由 `[target]` 推出前缀和 cflags；
2. 把 store 里工具链的 `bin/` 前置到 `PATH`，工具链探测就能选中 `arm-none-eabi-gcc` 而不是宿主 `gcc`；
3. 源码包变成构建图里的目标，二进制依赖的 `include/`、`lib/` 加进命令行；
4. 子进程继承叠加后的 `PATH`、`CFLAGS`、`LDFLAGS`、`CPATH`。

声明了工具链但未安装时报错，不回退到宿主编译器：

```
heddle: managed toolchain 'arm-none-eabi' is not installed
        (compiler 'arm-none-eabi-gcc' not found); run 'heddle tool install'
```

## 命令

| 命令 | 含义 |
| --- | --- |
| `heddle tool install` | 恢复工具链和依赖，写 `heddle.lock` |
| `heddle tool plan` | 只打印解析计划 |
| `heddle env verify` | 对比 store 和锁 |

| 选项 | 含义 |
| --- | --- |
| `--registry DIR\|URL` | registry 位置，默认 `$HEDDLE_REGISTRY` |
| `--offline` | 不访问 registry |
| `-v`, `--verbose` | 打印每个包和哈希 |
